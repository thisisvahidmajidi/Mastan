# گزارش تست نهایی پلتفرم CoachRoom OD — نسخه ۱.۵.۰

## ۱. هدف این نسخه

- گسترش فرم ارزیابی از ۱۰ شاخص کلی به **۳۰ سؤال دقیق** (۳ سؤال در هر بُعد) برای افزایش دقت پردازش و پشتیبانی بهتر تصمیم مدیران.
- حذف راهبرد پیش‌فرض «ارتقای سرپرستان به مربیان عملکردی» و جایگزینی با **موتور انتخاب تطبیقی راهبرد** بر اساس بلوغ واقعی سازمان.
- اطمینان از این‌که چرخه «دریافت سؤال‌ها → ذخیره → میانگین بُعد → تحلیل → راهبرد → OKR → نقشه راه → گزارش» کاملاً یکپارچه و بدون خطای خاموش است.
- به‌روزرسانی تست خودکار و مستندات نهایی.

## ۲. اصلاحات فنی انجام‌شده

### فرم و ذخیره‌سازی سؤال‌به‌سؤال

| موضوع | جزئیات |
|---|---|
| بانک سؤال | `questions()` در `class-cr-od-helpers.php` با ۳۰ سؤال (۳ سؤال در هر یک از ۱۰ بُعد) و برچسب ۴ گزینه‌ای `question_options()`. |
| ستون‌های پایگاه داده | جدول `responses` دارای `question_key` و `question_label` و ایندکس `question_key` است؛ `maybe_upgrade()` ستون‌ها را هنگام ارتقا اضافه می‌کند. |
| ذخیره | `insert_response()` سؤال، برچسب، امتیاز و وزن بُعد را ذخیره می‌کند؛ در فرم جدید هر پاسخ یک سطر سؤال‌محور است. |
| میانگین بُعد | در AJAX میانگین دقیق حسابی سؤال‌های هر بُعد محاسبه می‌شود (`sum/count`) و به همان شکل در پردازش و خروجی استفاده می‌شود. |
| سازگاری | فرم/API قدیمی (فقط `dimensions`) همچنان پشتیبانی می‌شود، اما فرم جدید از `questions` استفاده می‌کند. |

### انتخاب تطبیقی راهبرد

| موضوع | جزئیات |
|---|---|
| موتور راهبرد | `strategies()` + `strategy_data()` در helpers، راهبردها را بر اساس آستانه‌های بلوغ برمی‌گزیند. |
| آستانه‌ها | امنیت روانی ≥ ۲.۵، شنیدن فعال/پرسش‌گری/بازخورد ≥ ۲.۲، ساختار (رسمیت/تمرکز/پیچیدگی) ≥ ۲.۰. |
| شرط مربی‌گری | راهبرد «ارتقای نقش سرپرستان به مربیان عملکردی» فقط وقتی فعال می‌شود که همه پیش‌نیازها تأیید شوند و نمره فرهنگ مربی‌گری در محدوده نیاز باشد. |
| حذف هوشمند | اگر آمادگی تأیید نشود، راهبرد مربی‌گری از OKR، اقدامات اولویت‌دار و نقشه راه به‌تعویق می‌افتد و دلیل آن برای مدیر نمایش داده می‌شود. |
| نقشه راه | سه فاز ۳۰/۶۰/۹۰ روزه از راهبردهای منتخب ساخته می‌شوند؛ تیتر و متن دیگر «پیش‌فرض مربی‌گری» نیستند. |
| به‌روزرسانی زنده | بعد از هر ثبت ارزیابی، بخش `cr-strategy-note` و سه فاز نقشه راه با داده جدید بازسازی می‌شوند. |

### یکپارچگی ورودی → خروجی

| موضوع | جزئیات |
|---|---|
| فرم | همه ۳۰ سؤال به‌صورت الزامی جمع‌آوری و در یک درخواست AJAX ارسال می‌شوند. |
| ذخیره | فقط پاسخ «همان نقش + همان واحد + همان بُعد» جایگزین و داده نقش‌های دیگر حفظ می‌شود. |
| تحلیل | `analysis_data()` خلاصه، نقاط قوت/ضعف و جمع‌بندی را از داده ثبت‌شده می‌سازد. |
| OKR | از شاخص‌های ضعیف ساخته می‌شود؛ شاخص مربی‌گری در صورت عدم آمادگی حذف می‌شود. |
| گزارش | نتیجه‌گیری، دستورالعمل ۹۰ روزه، جدول نقشه راه OKR و اقدامات اولویت‌دار از همان داده‌ها تولید می‌شوند. |
| سلامت | صفحه سلامت داده و `selfTest()` در مرورگر صحت ساختار را بررسی می‌کنند. |

## ۳. چک‌لیست تست اجراشده

- [x] `node --check coachroom-od-platform/assets/js/coachroom-od-platform.js` — بدون خطای سینتکس.
- [x] بررسی توازن `{ }` و `[ ]` در همه فایل‌های PHP — بدون مشکل.
- [x] مقایسه شناسه‌های DOM در JS با شناسه‌های موجود در HTML — همه شناسه‌ها از جمله `cr-strategy-note` و `cr-roadmap-phase-30/60/90` موجودند.
- [x] بررسی وجود ۲۸ شناسه موردنیاز تست خودکار (داشبورد، فرم، جدول‌ها، EFQM، OKR، نقشه راه تطبیقی).
- [x] بررسی وجود ۳۰ سؤال در `questions()` و ۱۰ بُعد در `dimensions()`.
- [x] بررسی عدم انتخاب پیش‌فرض راهبرد «ارتقای سرپرستان به مربیان عملکردی»؛ در داده نمایشی موج دوم، این راهبرد به دلیل نمره پایین پیش‌نیازها غیرفعال است.
- [x] بررسی میانگین حسابی سؤال‌های هر بُعد در AJAX به‌جای میانگین تدریجی.
- [x] بررسی حذف `coaching_culture` از OKR و اقدامات اولویت‌دار وقتی موتور راهبرد آن را تأیید نمی‌کند.
- [x] بررسی به‌روزرسانی زنده بخش راهبرد پس از ثبت ارزیابی.
- [x] بررسی حفظ داده نقش‌های مختلف هنگام ثبت هم‌زمان.
- [x] بررسی وجود نمودارها، جدول‌ها، خروجی CSV و تب بلاگ/EFQM/OKR.

## ۴. سناریوی تست کاربری توصیه‌شده در سایت

1. تب **ارزیابی سازمانی** را باز کنید و ۳۰ سؤال را به‌صورت ۳ سؤال در هر ۱۰ بُعد ببینید.
2. واحد را انتخاب و نقش «کارمند» را بگذارید؛ همه ۳۰ سؤال را ثبت کنید.
3. دوباره همان واحد را با نقش «سرپرست» ارزیابی کنید؛ داده نقش قبلی حفظ شود.
4. به تب **نقشه راه** بروید: تیتر باید «نقشه راه تطبیقی توسعه سازمانی» باشد و اگر پیش‌نیازها آماده نباشند، مربی‌گری غیرفعال و دلیل آن نمایش داده شود.
5. به تب **گزارش مدیران** بروید: نتیجه‌گیری، دستورالعمل ۹۰ روزه، جدول OKR و اقدامات اولویت‌دار باید با راهبرد منتخب هماهنگ باشند.
6. خروجی CSV را دانلود کنید و ستون‌های ابعاد، واحدها و نقش‌ها را بررسی کنید.
7. روی واژه‌های ESG، EFQM، OKR، RADAR یا SBI hover کنید تا راهنمای شناور دیده شود.

## ۵. نتیجه

راهبردهای توسعه دیگر از پیش تحمیل نمی‌شوند؛ همه خروجی‌ها از داده‌های واقعی ۳۰ سؤالی مشتق می‌شوند. چرخه «ارزیابی سؤال‌به‌سؤال → میانگین بُعد → تشخیص بلوغ → انتخاب راهبرد → OKR → نقشه راه → گزارش مدیران» به‌صورت یکپارچه بسته شده است. نسخه تست‌شده به‌عنوان فایل `coachroom-od-platform.zip` تحویل داده می‌شود.
